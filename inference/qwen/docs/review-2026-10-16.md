## Findings corrected

1. **Shared runtime portability:** the extracted installer could use a managed
   interpreter in the installer's private home. It now installs managed Python
   under the chosen runtime directory, copies package files, verifies the base
   interpreter location, and refuses to overwrite an existing environment.
   This restores a property of the original shared deployment.
2. **Runtime identity across resume:** a Python path through `current` could
   silently select a different release after a symlink switch. Submission now
   resolves directory aliases while preserving the final venv executable entry.
   In-place runtime/model modification remains unsupported; binary/weight hashing
   on every submission is deliberately not added.
3. **Schema narrowing:** optional citation constraints replaced original enum,
   maximum, item and minimum-length constraints. They now intersect those
   constraints, validate chunk-map shape and enforce one-based integer chunk IDs.
   This preserves the supplied application schema. The feature stays optional
   and tied to its documented field convention; it is not a general schema
   rewriting framework or semantic evidence validator. Intersections use direct
   enum/bound merging: the installed XGrammar backend only partially supports
   multi-option `allOf`, so wrapping constraints in `allOf` is insufficient here.
4. **Stopping during retries:** a stop request or expired deadline could still
   start another full generation attempt. The worker now commits the attempt
   already completed without starting that retry. Slurm may still kill an
   in-flight batch before commit; the existing resume mechanism recomputes it.
5. **Configuration mismatches:** an omitted thinking flag could leave generation
   in Qwen's default thinking mode while parsing assumed it was off. The flag is
   now required explicitly. Parallelism sizes inconsistent with the one-GPU
   allocation are rejected before model load.

## Architecture assessment

The current design is appropriate for independent document batches: use
[vLLM's offline chat API](https://docs.vllm.ai/en/v0.31.0/serving/offline_inference/)
inside [Slurm array tasks](https://docs.together.ai/docs/slurm), with a model replica
per GPU and filesystem checkpoints. vLLM performs GPU scheduling; Slurm controls
allocation; the runner adds application-schema validation and durable progress.
An API server, Ray cluster, Kubernetes deployment, queue database, plugin registry,
or custom model hot-reload mechanism would add machinery without meeting a
current requirement.

Keep the pinned environment in a fresh runtime directory, consistent with
[vLLM's installation guidance](https://docs.vllm.ai/en/v0.31.0/getting_started/installation/gpu/).
Use `StructuredOutputsParams` for the final JSON, with the reasoning gate
configured separately, following the [structured-output API](https://docs.vllm.ai/en/v0.31.0/features/structured_outputs/)
and [thinking-budget interface](https://docs.vllm.ai/en/v0.31.0/features/reasoning_outputs/).
The installed runtime was checked directly because field placement and defaults
can vary between vLLM versions.

The current chunked-prefill/token-batch settings are consistent with
[vLLM's throughput tuning guidance](https://docs.vllm.ai/en/v0.31.0/configuration/optimization/).
They are workload-specific, not proof of optimal throughput. Retain the compile
cache and existing BF16/auto KV behavior, and benchmark before changing sequence
count, context limits, cache precision or sampling. Temperature 0 is a historical
comparison setting; [Qwen's recommended sampling](https://huggingface.co/Qwen/Qwen3.8-27B-FP8#best-practices)
is documented as a separate experiment rather than silently replacing it.

## Validation and limits

- 36 CPU tests pass, including the added schema-preservation, configuration,
  release-path, installer-preservation and stop-during-retry regressions.
- Shell syntax checks pass for installation and the Slurm batch script.
- All three shipped profiles pass real-tokenizer preflight and construction of
  `EngineArgs`, `SamplingParams`, `StructuredOutputsParams`, and applicable
  `ReasoningConfig`/`RepetitionDetectionParams` in the installed cluster runtime.
  The synthetic request rendered to 112 tokens with thinking off and 151 with it on.
- The recorded package snapshot and original default profile were compared live,
  not inferred from local historical notes.
- The revised citation schema compiled with installed XGrammar; its matcher
  accepted a valid JSON answer and rejected an answer exceeding the original
  chunk bound. This checks actual decoding-grammar behavior in addition to the
  JSON Schema unit tests.

No new environment installation, GPU generation, job submission, or shared-release
mutation was performed. Before release promotion, run the documented one-GPU
smoke test and interruption/resume check with the new launcher. Existing runs
must continue using their saved code and original launcher; the new launcher's
`python.txt` metadata is not present in old runs. Multi-GPU models, interactive
serving, arbitrary reasoning parsers and very large unsharded manifests remain
outside this implementation's validated scope.

## Later changes

After this review, request rows (`REQUESTS.md`) moved application logic out of the
runner. Citation narrowing (finding 3) now belongs to applications, which write a
narrowed schema into each request; the runner rejects `citation_constraints`.
Retries are limited to format failures with an optional temperature schedule, the
thinking profiles use the model card's sampling, `thinking_budget_exhausted` no
longer counts the closing token as a cap, and releases are built from a commit with
`scripts/build_release.sh`.
